# FIELDNOTES

## 前端与高级古雅视觉设计系统

**FIELDNOTES Design System · Editorial Classicism × Cobalt Celestial Engraving**  
版本：**v1.0 · 2026-11-01**  
适用：AI Interview Lab 网页、每日学习卡片、知识专题封面、原创新插画、设计复盘与后续前端改版  
项目：[HardZionL/ai-interview-lab](https://github.com/HardZionL/ai-interview-lab)

> **风格一句话定义：** 以编辑杂志的秩序组织学习，以古典艺术的静穆表达思考，以精细版画与天体图谱表现知识探索；界面克制，插画鲜明，留白是设计的一部分。

> **重要区分：** 本文记录“当前 V5 前端实现”与“后续推荐的目标规范”。二者若存在差异会明确说明，不将尚未实现的改造写成已上线功能。

## 01｜设计理念与品牌性格

FIELDNOTES 不是炫技型 AI Dashboard，也不是靠大量霓虹渐变堆砌出来的科幻网站。它是一个安静、深度、可持续使用的 **AI 面试学习手帖（Study Journal）**：阅读时有纸张与图录的秩序，交互时有工程工具的可靠性。

| 关键词 | 应当如何体现 | 应避免的方向 |
|---|---|---|
| 高级（Refined） | 对齐、克制、精密留白、清晰信息层次 | 过多卡片阴影、浮夸动画、堆叠装饰 |
| 古雅（Classical） | 衬线标题、石雕、柱式、蚀刻排线 | 米黄色旧纸、粗暴复古滤镜、博物馆式僵硬排版 |
| 神秘（Enigmatic） | 星图、轨道、远山、拱门与未知空间 | 满屏黑色宇宙背景、随机科技图标 |
| 理性（Scholarly） | 编号、知识出处、目录、阶段与笔记 | 无来源的概念图和装饰性数据 |
| 鲜活（Alive） | 局部钴蓝、精准悬停反馈、动态当天题目 | 花哨的闪烁、自动播放、滚动劫持 |

**不可妥协的设计原则：** 内容优先、主体清晰、留白有意义；图像承担叙事而不是填满空白；所有可见的学习入口都应有真实可用的交互。

## 02｜双层色彩系统

本项目有两个不同的“白”，必须分清楚：

**A. 前端 UI 纸面层（当前 V5）：** 使用轻暖白 `#F9F8F6`，墨黑 `#1C1C1C`，线色 `#D8D5CE`，主要蓝色变量 `#1937E4`。这属于已检查的网页 CSS 实现，用在导航、主内容、卡片与文字。

**B. 插画资产层（用户确认的目标）：** **纯白 `#FFFFFF`** 为完整背景，钴蓝主色建议 `#174BFF`，辅以深钴蓝 `#1036B8`、墨黑雕刻 `#171717` 和柔和中性灰。纯白色是插画硬性要求，不能偷偷替换为米黄、灰黄或复古纸色。

| Token / 用途 | 值 | 设计规则 |
|---|---|---|
| `--ui-paper` | `#F9F8F6` | 当前网页纸面底；未来如统一纯白，需要整体审视对比度 |
| `--art-paper` | `#FFFFFF` | 原创插画背景，必须纯白 |
| `--ink` | `#1C1C1C` | 主要正文、标题、图形轮廓 |
| `--cobalt-ui` | `#1937E4` | 当前交互强调色（依据 V5 CSS） |
| `--cobalt-art` | `#174BFF` | 插画主体中的高饱和钴蓝 |
| `--cobalt-deep` | `#1036B8` | 局部阴影或深空，不得铺满背景 |
| `--line` | `#D8D5CE` | 细边框、区块分隔线 |
| `--muted` | `#66635F` | 次级说明文字，须保持可读性 |

视觉比例建议：纸面与留白 **55–70%**；黑白雕刻与文字 **20–35%**；鲜明钴蓝 **5–15%**。这是设计指导比例，不是图像像素的自动验算标准。

## 03｜字体系统与阅读节奏

**标题用衬线、正文优先易读，英文标签采用宽字距的小型大写字母。** 不通过不断加粗来建立层级，而以尺寸、留白和分隔线控制阅读顺序。

| 层级 | 建议 | 典型位置 |
|---|---|---|
| Display | 古典高对比衬线；桌面约 45–63px（随视口缩放） | `AI INTERVIEW LAB` Hero 标题 |
| H1 / H2 | 衬线、正常字重、紧凑字距，中文具文气但不晦涩 | 每日五题标题、面试题题干 |
| Body | 易读中文无衬线或温和衬线；行高约 1.7–1.9 | 学习讲解、题目描述、复盘 |
| Label | 9–11px，增加字距，英文大写 | `TODAY'S TASK`、`DAY 04`、图录索引 |
| Metadata | 低对比但不失可读性；数字等宽或清晰对齐 | 日期、分数、题目状态、版本号 |

当前 CSS 的衬线回退包含 `Iowan Old Style / Baskerville / Songti SC / Georgia`，无衬线回退包含 `PingFang SC / Microsoft YaHei / Helvetica Neue / Arial`。跨设备不能依赖单一字体，最终以浏览器实际字形为准。

## 04｜已确认的桌面布局骨架

### 4.1 信息架构

```text
┌───────────────────────────────────────────────────────────────┐
│ FIELDNOTES  | HOME / STUDY / LIBRARY ...       品牌说明 / 星芒 │
├────────────┬───────────────────────────────┬───────────────────┤
│ 左侧目录栏 │         Hero 主视觉            │ Hero 延展至右侧     │
│ DAY / 日期 │  英文标题 / 中文副标题 / 雕塑拼贴与星图           │
│ 当日五题   ├───────────────────────────────┼───────────────────┤
│ 学习阶段   │ 每日任务卡 / 经典引言         │ 学习进度           │
│ 学习工具   ├───────────────────────────────┤ 圆环 + 五题状态    │
│ 底部短句   │ 三张当日推荐卡（图片在上）   │ 今日目标与说明     │
│            ├───────────────────────────────┤                   │
│            │ 当日题卡 + 口述训练 + 核对    │                   │
└────────────┴───────────────────────────────┴───────────────────┘
```

**当前 V5 桌面实现**：网站顶部 Header 约 **91px**；主网格 `240px minmax(0,1fr) 375px`，最大宽度约 **1800px**；左侧目录采用 sticky；Hero 横跨中央与右侧，约 **330px** 高，内部约 **43% 文案 / 57% 插画**；中央任务下方为三张等宽卡片，右侧为学习进度。以上是当前代码值，设计升级时可以微调，**不应把具体像素当作任何设备都适用的死值**。

### 4.2 左侧目录（Navigation Rail）

- 首屏明确展示 `DAY NN` 与日期，帮助用户知道自己正学哪一天。
- 当天五题目录必须来自当前选中 Day 的真实数据，不是手工写死的示例。
- 选中态通过细微背景、边线或钴蓝提示；未解锁题目明确提示，不制造失效按钮。
- “深入学习、独立口述、要点核对、自适应巩固”应与学习流程一致。
- 学习工具区包含笔记、学习记录与 JSON 导入/导出入口。

### 4.3 Hero 主视觉

- 左侧是标题、中文短句与 21 天学习路径简述；右侧是大幅古典雕塑与星图拼贴。
- 以左文右图形成张力，不让英文大标题侵入石雕主体的面部。
- 图片应为独立高清素材，避免把按钮、文字和完整网页效果图烙进背景。
- `object-fit: cover` 时必须核对主体不被裁断；必要时使用不同断点的专用裁切版本。
- 背景细节如果延伸到学习区，应降低存在感和对比度，不能妨碍口述输入。

### 4.4 当日任务 + 推荐三卡

- 每日任务区：`TODAY'S TASK / DAY NN`、五题目标、简短说明、开始学习按钮，以及可选的引用语。
- 下方三张推荐卡：**图在上 / 题目标题 / 简介 / 真实学习入口**，维持相同纵向节奏与清晰对齐。
- 推荐内容与题目编号随 `selectedDay` 变化：读取 `DAYS[selectedDay - 1]` 中的当日题目；绝不能永远指向 Day 1。
- 三张卡片代表当日内容的入口，不是只有视觉而无法进入题目。

### 4.5 右侧学习进度

- 独立窄栏：`DAY NN / 21`、圆环完成度 `x/5`、当日五题逐题状态。
- 在环形指标后保留今日目标、鼓励文字和适当留白，不用过量图表。
- 状态必须与浏览器实际学习记录同步；不要模拟“已完成”或伪造评分。

## 05｜图像设计：白底钴蓝高级古雅

### 5.1 核心视觉母题

古典石膏雕塑、柱式与门廊、雕花羽翼、手与天体、披风探索者、巍峨群山；搭配月面、星云、轨道椭圆、天球网格、精细坐标线、十字星芒、局部钴蓝几何拼贴。将“知识、探索、记忆、连接、创造、持续学习”转为可被观看的象征。

### 5.2 材质与光感

- 采用细腻的铜版蚀刻、钢笔排线、点描、轻微印刷网点；雕像应有真实石材明暗层次。
- 高反差用于主体结构，低反差用于辅助图谱；避免一片黑或蓝色霓虹灼烧。
- **画面边缘保留白场**，主体与轨道线不必占满四个角落。
- 图像应有微观细节，但缩小为网页卡片后依然能读出主体轮廓。

### 5.3 系列主题资产库（八图）

| 编号 | 主题 | 推荐主体 / 隐喻 |
|---|---|---|
| 01 | ORBITAL MIND | 古典胸像、蓝色天体与知识轨道 |
| 02 | MESSENGER | 单只高精细羽翼与星图测绘线 |
| 03 | THRESHOLD | 拱门、银河与小型探索者 |
| 04 | ASCENT | 飞升古典形体、星芒和云层 |
| 05 | RECOLLECTION | 侧脸、像素裂变与记忆碎片 |
| 06 | FARTHER STUDIES | 巨月、山脉、披风旅人 |
| 07 | THE OPEN HAND | 装饰性拱框、蛇形纹样与托举星球的手 |
| 08 | CONTINUUM | 仰望雕像、环绕轨道、时间流动 |

允许在未来加入中国古代雕塑与数字几何元素，但**必须单独建立子系列**，先生成审核样张，不随意改变主系列的视觉一致性。

### 5.4 图像规格与格式

- 单张立绘：高分辨率 PNG 母版，常见竖版比例接近 `3:4` 或画廊展示比例（按构图选择，不强制一律相同）。
- 视觉图录：整齐四列两行网格；但**上传资源应为八张独立单图**，不可只交付一张总拼图。
- 网站推荐卡横版：建议约 `2.4:1`（例如 `1942×809`），通过独立横向构图或有意识的裁切制作。
- 上传网站时保留高质量 WebP；母版 PNG 独立归档；图片加清晰文件名和 `alt` 描述。
- **不能通过普通放大宣称恢复原不存在的纹理细节。** 需区分 AI 重绘与插值锐化。

## 06｜交互原则：美学服从学习体验

1. **按天联动**：选择 Day 后，Hero 的主题说明、五题索引、推荐三卡、进度环同步读取当前日期题目数据。
2. **切题不回顶部**：点击 `01–05`、上一题/下一题，应把当前问题标题定位到可读位置，并避开 sticky Header。
3. **口述优先**：先学原理，再让用户独立回答，之后展示答题要点和原站链接，不用五道超短选择题代替深度理解。
4. **自适应明确**：区分“补基础 / 巩固 / 深化追问 / 新知识点”；当前版本是规则驱动，不宣称由在线大模型完成语义评分。
5. **反馈不过度打扰**：Toast 在空闲状态必须隐藏；仅在明确的成功、错误或提示事件后出现并消失。
6. **状态真实**：显示的完成数、得分和题目状态必须来自实际保存的数据；未保存的操作不能虚称成功。
7. **无障碍**：键盘可操作、焦点清晰、语义化按钮、有效的 alt、移动端触控舒适，尊重减少动态效果的系统设置。
8. **动效克制**：可用轻微淡入、边线变化、图片缓慢缩放；避免页面跳动、过度视差和动画遮挡文字。

## 07｜技术约束与数据保护

现有站点是原生 HTML / CSS / JavaScript 静态网站，GitHub Pages 托管。学习记录使用浏览器 `localStorage`，现有关键存储标识为 `fieldnotes_interview_v3`。不要随意更改存储键、记录结构或 JSON 备份格式，否则可能使已有进度无法读取。

- Day 1 = **2026-10-17**，学习日期按 **Asia/Singapore** 计算。
- 每日五题、总计 21 天 / 105 条学习路径；题目深度和原文核验程度存在差异，不能误称 105 题均完整验证。
- 静态网站**不具备跨设备云同步**；跨设备迁移应由用户导出并导入 JSON。
- 不把 API Key、Token、隐私备份、口述记录上传至公共 GitHub 仓库。
- 保留 [小林面试笔记 AI 专题](https://xiaolinnote.com/ai/) 的来源致谢，并区分原作者内容与本项目独立整理内容。
- 不直接复制 Hermes 官方插画、Logo 或耳机女孩角色；古典艺术、羽翼、星图属于可重新创作的通用视觉母题，但具体构图要保持原创。

## 09｜可复用绘画提示词

### 中文主提示词（竖图）

## 10｜审核、交付与版本管理流程

**创作前：** 明确用途（Hero / 竖图 / 网站横卡 / 小装饰）、像素尺寸、构图主题和留白位置；核对现有素材，避免重复使用相同雕像头像。

**创作中：** 单幅独立生成 → 检查主体与纯白背景 → 选择性修正钴蓝和纹理 → PNG 母版 → WebP 优化 → 网页真实尺寸预览。

**提交前：** 提供单图及拼版供用户确认；用户未审核通过，不直接更新公开网站。对已有图片采取**新文件入库 + 旧版备份**策略。

**提交时：** 先备份 `main` 分支；独立图片归档至 `assets/archive/<series>/`；只在确认后更新指定 `assets/card-*.webp` 或 Hero 引用；附上版本说明与来源/授权声明。

**回归检查：** 逐项测试 Day 1 / Day 4 / 任一后期 Day 的推荐内容、五题链接、滚动、口述、评分、JSON 导入导出、桌面与移动端；确认 GitHub Pages 构建与实际页面图片加载。

### 验收清单

- [ ] 页面三栏结构与 Hero、任务卡、三张推荐卡、右侧进度一致。
- [ ] 插画背景为纯白，钴蓝与黑白雕刻平衡；留白充分。
- [ ] 单图独立交付，PNG 母版与 WebP 网站版均保存。
